대상 diff를 정한다(인자로 커밋/범위가 주어지면 그것을, 없으면 스테이징 있으면 `--cached`, 없으면 최근 커밋을 사용). 필요하면 `CLAUDE.md`/`GOLDEN_RULES.md`(해당 하위 프로젝트 것 우선)도 참고한다.

diff를 아래 5축으로 채점한다. 각 축은 만점을 넘지 않으며, 점수가 0이 아니면 반드시 근거를 한 줄로 남긴다(추측 금지 — 근거 없으면 0점).

1. **Security (30점 만점)** — 시크릿/키 하드코딩, 인증·권한 로직 변경, 입력 검증 약화, 로그에 민감정보 노출 등.
2. **Scope (20점 만점)** — 요청/목적과 무관한 파일·라인이 섞였는가(Surgical 원칙 위반), diff가 여러 무관한 관심사를 동시에 건드리는가.
3. **Breaking (20점 만점)** — 기존 함수/API 시그니처·exports·응답 스펙이 호출부 갱신 없이 바뀌었는가, 하위 호환을 깨는가.
4. **Tests (15점 만점)** — 변경에 대응하는 테스트가 없거나, 기존 테스트를 깨뜨렸는가(가능하면 실제로 테스트를 실행해서 확인한다).
5. **Migration (15점 만점)** — 데이터/스키마/설정 마이그레이션이 필요한데 없는가, 배포 순서·롤백 계획이 누락됐는가.

각 축은 diff와 실제 실행 결과(테스트 등)로 확인 가능한 근거만 인정한다. 근거가 없으면 그 축은 0점으로 채점한다.

## 등급

총점 = 5축 합산 (최대 100점).

- 🟢 0~15
- 🟡 16~35
- 🟠 36~60
- 🔴 61+

## 등급별 권장 액션 (우리 팀 버전)

- 🟢 셀프 머지 가능
- 🟡 동료 1명 리뷰
- 🟠 교수님 리뷰
- 🔴 머지 보류 · 설계 논의
