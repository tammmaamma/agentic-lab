# repo-grade

이 저장소가 "agent가 일하기 좋은 상태"인지 100점 만점으로 채점하는 스킬.

## 절차

1. 실제 파일을 읽는다 — README, CLAUDE.md, GOLDEN_RULES.md, docs/, 소스 구조, 테스트 파일. 추측으로 채점하지 않는다.
2. 가능하면 검증 명령(`npm test` 등)을 직접 실행해 결과를 확인한다.
3. 아래 루브릭의 5개 카테고리를 각각 0 / 10 / 20점 중 하나로 채점하고, 근거로 구체적인 파일·줄을 남긴다.
4. "출력 형식"에 정의된 형식 그대로 결과를 보여준다.

## 루브릭 (5개 카테고리 × 20점 = 100점)

### A. 길 안내 — 진입점·핵심 파일 안내가 있는가

| 점수 | 기준 |
|---|---|
| 0 | 안내 문서가 없거나, 있어도 진입점·핵심 파일 언급이 전혀 없다 |
| 10 | 진입점은 언급되지만 핵심 파일/폴더 구조 설명이 부분적이거나 실제 구조와 어긋난다 |
| 20 | README/CLAUDE.md에 진입점과 핵심 파일·폴더가 명확히 안내되어 있고 실제 구조와 일치한다 |

### B. 규칙 문서 품질 — CLAUDE.md가 간결하고 명령어·금지사항을 담는가

| 점수 | 기준 |
|---|---|
| 0 | CLAUDE.md가 없거나, 있어도 명령어·금지사항이 없다 |
| 10 | 명령어·금지사항은 있지만 35줄을 넘거나 장황해 나침반 역할을 못 한다 |
| 20 | 35줄 이내로 간결하며 명령어·금지사항이 명확히 담겨 있다 |

### C. 숨은 규칙 문서화 — Why·Gotcha가 기록되어 있는가

| 점수 | 기준 |
|---|---|
| 0 | "왜 이렇게 했는지", "여기 함정" 같은 기록이 전혀 없다 |
| 10 | 코드 주석·커밋 메시지 등에 단편적으로만 남아있다 |
| 20 | Why·Gotcha가 CLAUDE.md/docs/코드 주석 등에 체계적으로 기록되어 있다 |

### D. 검증 게이트 — 테스트가 존재하고 npm test로 확인 가능한가

| 점수 | 기준 |
|---|---|
| 0 | 테스트가 없거나 실행이 안 된다 |
| 10 | 테스트는 있지만 커버리지가 얕거나 실행 방법이 불명확하다 |
| 20 | `npm test`(또는 동등 명령)로 바로 실행되고 핵심 로직을 커버하며 통과한다 |

### E. 신선도 — 문서가 최근 코드와 일치하는가

| 점수 | 기준 |
|---|---|
| 0 | 문서가 코드와 명백히 어긋난다(존재하지 않는 파일·틀린 값 언급 등) |
| 10 | 대체로 일치하지만 일부 항목이 낡았거나 불명확하다 |
| 20 | 문서의 모든 항목이 현재 코드와 정확히 일치한다 |

## 출력 형식

반드시 아래 순서·형식으로 출력한다.

1. **채점 표**

   | 카테고리 | 점수 | 근거 | 개선 제안 |
   |---|---|---|---|
   | A. 길 안내 | | | |
   | B. 규칙 문서 품질 | | | |
   | C. 숨은 규칙 문서화 | | | |
   | D. 검증 게이트 | | | |
   | E. 신선도 | | | |

2. **총점**: `xx / 100`

3. **ROI 순 개선 3가지** — 적은 노력으로 큰 점수 상승이 가능한 순서로 정렬. 각 항목에 예상 소요와 예상 점수 상승을 함께 적는다.
